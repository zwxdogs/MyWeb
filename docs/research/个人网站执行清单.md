# 个人网站执行清单（阶段 0–10 验收版）

> **用途**：从 [个人网站制作调研.md](个人网站制作调研.md) 第三章提炼出来的可执行版本。调研文档讲"为什么"，这份只讲"做到什么算过"。
> **用法**：按阶段往下走，每个阶段的勾选全部打完才进入下一阶段；卡住时回调研文档对应小节看依据。
> **口径**：验收项来自调研文档；标【经验】的是工程经验阈值，不是官方规定。

**总览**

| 阶段 | 产出 | 必做 | 预估【估算】 |
| --- | --- | --- | --- |
| 0 需求与定位 | `docs/plan.md` | 是 | 1–2 小时 |
| 1 选型 | 一页选型记录 | 是 | 1 小时 |
| 2 初始化 | 能跑的最小仓库 | 是 | 30 分钟 |
| 3 本地开发 | 本地可预览站点 + 命令小抄 | 是 | 1 小时 |
| 4 内容与页面 | 页面与样式 | 是 | **占全流程 45%** |
| 5 质量检查 | 检查记录 | 是 | 1–2 小时 |
| 6 版本管理 | 干净提交历史 | 是 | 贯穿全程 |
| 7 构建与部署 | 线上 URL | 是 | 1 小时 |
| 8 上线检查 | 逐项打勾的清单 | 是 | 1 小时 |
| 9 持续维护 | 维护日历 | 上线后 | 长期 |
| 10 时间估算 | —— | 参考 | —— |

## 阶段 0 · 需求与定位

- [ ] 写下一句话定位：给谁看、看什么、看完做什么
- [ ] 定站点类型（作品集 / 博客 / 简历 / 技术文档），只选一个
- [ ] 列页面清单：首页、列表、详情、关于、404
- [ ] 定义内容模型起步字段：标题、日期、描述、标签
- [ ] 产出 `docs/plan.md`：一句话定位 + 页面表 + 字段表

**过关**：随便挑一个页面，能立刻说清"数据从哪来、由谁渲染"。

> 坑：先搭框架再想内容，返工最贵【经验】。用 Hugo 时 `draft = true` 默认不构建，忘改就是"文章消失"。

---

## 阶段 1 · 选型

- [ ] 回答三问：要写 Markdown 吗 → 要登录/数据库/评论吗 → 愿意维护服务器吗
- [ ] 写下选型记录：框架 + 理由 + 被放弃的选项及原因

**过关**：能写出一句完整的"选 X 因为 Y，不选 Z 因为 W"。

> 坑：跟着教程热度选型，不看它是否真支持 Markdown 与静态产出【经验】。

---

## 阶段 2 · 初始化

- [ ] 跑通脚手架命令（见下），目录里出现最小骨架
- [ ] `.gitignore` 就位（Astro 官方模板含 `.astro/`、`.env`、`dist/`、`node_modules/`）
- [ ] 首次 `git init -b main`（Git 2.x 默认仍是 `master`，Git 3.0 才改）

脚手架命令对照：

| 框架 | 命令 | 前置 |
| --- | --- | --- |
| Astro | `npm create astro@latest` | Node ≥ v22.23.4，奇数版（如 v23）不支持 |
| Hugo | `hugo new project <path>` | `hugo new site` 已从官方文档移除，旧链接是 404；Windows 需 PowerShell 7 或 bash |
| Next.js | `npx create-next-app@latest --yes` | Node ≥ 20.9 |

**过关**：`npm run dev`（Astro 默认 `http://localhost:4321/`）或 `hugo server` 能起站。

> 坑：Astro 官方明确必须本地安装，`npm install -g astro` 不成立。

---

## 阶段 3 · 本地开发

- [ ] 认清目录职责：`src/pages`（文件即路由）/ `src/layouts` / `public/`（Astro）；`content/` / `layouts/` / `static/`（Hugo）
- [ ] 改一处文案，确认浏览器自动刷新，无需重启
- [ ] 写一张常用命令小抄（dev / build / preview）

**过关**：改文件 → 页面立刻更新。

> 坑：`hugo server` 报找不到主题——需先 `git submodule add` 拉主题并在配置里写 `theme`。

---

## 阶段 4 · 内容与页面开发

- [ ] 抽出 Layout 统一管 head、导航、footer，页面只填正文
- [ ] 静态路由全部建好（首页、关于、404）
- [ ] 列表页 + 详情页能按文件路径自动生成
- [ ] 样式：CSS 变量定色板与字号阶梯，组件级样式，移动优先断点
- [ ] 所有 `<img>` 写明 `width` / `height`（否则加载抖动伤 CLS）
- [ ] 每页有 `title` 与 `description`

**过关（三档一起过）**：

- [ ] 320 / 768 / 1440 三档宽度均无横向滚动
- [ ] 只用键盘 Tab 能走完全站，焦点可见
- [ ] 关掉 JS，主要内容仍可读【经验】

> 这是全流程 45% 的工时所在，别指望一晚上过完。

---

## 阶段 5 · 质量检查

- [ ] Lighthouse 跑一遍（DevTools 面板或 `lighthouse <url>`）
- [ ] HTML 校验：https://validator.w3.org/
- [ ] 断链检查：https://validator.w3.org/checklink
- [ ] 可访问性按 W3C WAI Easy Checks 人工过一遍
- [ ] 产出检查记录：工具、日期、问题清单、修复状态

**过关**：

- [ ] validator 0 error
- [ ] 断链 0
- [ ] Lighthouse 性能 / 无障碍 / 最佳实践 / SEO 四项 ≥ 90（阈值自定，非官方）

> 坑：Lighthouse 分只是自动项，绿分不等于合规——W3C 官方原话是"没有工具能单独判定是否达标，需要懂行的人来评估"。

---

## 阶段 6 · 版本管理

- [ ] 提交粒度：每次提交是一个孤立、完整的改动
- [ ] 默认分支始终保持可部署
- [ ] 改动走短分支 → PR → 合并 → 删分支
- [ ] 确认 `node_modules/`、`dist/` 没有进仓库

**过关**：

- [ ] `git log` 每条提交都能一句话说清
- [ ] 从默认分支重新 clone 能构建成功

---

## 阶段 7 · 构建与部署

- [ ] 本地构建成功（Astro `npm run build` → `dist/`；Hugo `hugo` → `public/`）
- [ ] `npm run preview` 本地验一遍构建产物
- [ ] 推到托管平台，拿到线上 URL
- [ ] 绑自定义域名（子域 CNAME / 裸域 A 记录）
- [ ] 开启强制 HTTPS

平台要点：

| 平台 | 关键约束 | 绑域名 |
| --- | --- | --- |
| GitHub Pages | 站点 ≤1GB、带宽软限 100GB/月、构建软限 10 次/小时、部署最长 10 分钟生效；非 Jekyll 生成器要放 `.nojekyll` | 子域 CNAME → `USERNAME.github.io`；裸域 A 记录 `185.199.108.153` / `.109` / `.110` / `.111`；域名总长须 < 64 字符 |
| Cloudflare Pages | Free 500 构建/月、2 万文件、单文件 25MiB | apex 域需先把站点接入 Cloudflare |

**过关**：

- [ ] 线上 URL 打开就是站点，不是 404
- [ ] `http://` 自动跳 `https://`
- [ ] 证书有效，无混合内容警告
- [ ] 手机 4G 下打开正常

> 坑：页面里残留 `http://` 资源即混合内容，浏览器判不安全。

---

## 阶段 8 · 上线检查

- [ ] sitemap 生成（Astro 需先在 `astro.config.mjs` 设 `site`）
- [ ] `robots.txt` 里加一行 `Sitemap:` 指向它
- [ ] 每页有 canonical 与 OG 标签（`og:title` / `og:description` / `og:image` / `og:url`）
- [ ] 自定义 404 页，且**真返回 404 状态码**（不能返回 200）
- [ ] favicon
- [ ] 分析统计接上（可选）

硬限制：单 sitemap ≤50MB 且 ≤5 万条 URL、UTF-8、绝对 URL；Google 忽略 `priority` / `changefreq`。

性能目标（第 75 百分位）：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1。

**过关**：

- [ ] Search Console 提交 sitemap 成功
- [ ] 随便打开一个不存在的 URL，返回 404 且显示自定义页
- [ ] 把链接发到自己微信/微博，预览卡片有标题与图

> 中国大陆服务器与备案主体：需 ICP 备案，官方入口 https://beian.miit.gov.cn/ （调研时未取得逐条要求，未核实；非法律意见）。托管在境外则此条不适用。

## 阶段 9 · 持续维护

- [ ] 定更新节奏（博客双周更 / 作品集随项目更新）
- [ ] 固定一天当"内容日"
- [ ] `npm outdated` 看依赖滞后，大版本升级前先读官方 upgrade 指南
- [ ] 建维护日历：内容 / 依赖 / 备份 三列

**过关**：每月至少完成一次依赖升级，且构建通过。

> 坑：装完就不管，依赖会烂；域名与证书到期日也记进日历【经验】。
