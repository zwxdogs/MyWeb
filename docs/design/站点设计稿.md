### 修正 1：日期不能用 `z.coerce.date()`

| | |
| --- | --- |
| **源裁定** | 探索票 [#5](https://github.com/zwxdogs/MyWeb/issues/5)（`04-projects-and-notes.md` 第 201 行）：「`date` 不能用 `z.string()` 裸写……⇒ 用 `z.coerce.date()`，**必须带日**」 |

| **性质** | **改判**。理由不是偏好，是原写法达不到原裁定自己写下的要求。 |

### 修正 2：论文的元信息行只渲染 `venue`，不拼 `year`

| | |
| --- | --- |
| **源裁定** | 探索票 [#4](https://github.com/zwxdogs/MyWeb/issues/4)（`03-papers-model.md`）同时写了两句互斥的话：①「`venue` 写成 `CVPR 2026` 这种**含年份**的形态，是因为『会议 + 年份』在页面上永远同一行出现」；②「模板渲染契约：**元信息行**：`venue` · `year`」 |

## 1. 站点是什么

一个在读博士生的个人网站。四块内容：个人介绍、论文发表、开发项目、日常分享。

- **受众**：学术同行、导师、未来的合作者。以学术展示与软件项目展示为主，不面向求职。
- **语言**：全中文。论文标题、会议名、技术名词保留英文原名——中文正文里硬翻「Transformer」为「变形金刚式网络」只会让人读不下去。
- **不是博客**：`/notes/` 这条路径叫 `notes` 而不是 `blog`，是因为它**不承诺博客语义**。站内没有 RSS、没有搜索、没有评论、没有标签归档；起了 `blog` 这个名字，读者会期待一个博客该有的东西，然后失望。

## 3. 页面与 URL

### 3.1 8 条路由

| 路由 | 产物文件 | 页面 |
| --- | --- | --- |
| `/` | `dist/index.html` | 首页（单页可下滑） |
| `/papers/` | `dist/papers/index.html` | 论文列表 |
| `/papers/<slug>/` | `dist/papers/<slug>/index.html` | 论文详情 |
| `/projects/` | `dist/projects/index.html` | 项目列表 |
| `/projects/<slug>/` | `dist/projects/<slug>/index.html` | 项目详情 |
| `/notes/` | `dist/notes/index.html` | 分享列表 |
| `/notes/<slug>/` | `dist/notes/<slug>/index.html` | 分享详情 |
| `/404.html` | `dist/404.html` | 本站 404 |

没有「关于」页。个人介绍只有一段话，塞在首页顶部即可；独立成页只会多一个几乎没人点的导航项，而导航已定为 4 项。

### 3.2 URL 形态：目录式，零配置

`build.format` 的默认值就是 `'directory'`【文档】，Astro 会把每个路由产成 `<路径>/index.html`。**不要写任何配置**——目录式是所有静态托管的最小公分母（EdgeOne / Cloudflare Pages / GitHub Pages / Vercel 都一致）。

**为什么不用文件式**：文件式（`/papers/deep-residual-learning.html`）想做成 `/papers/deep-residual-learning` 这种无扩展名访问，必须依赖平台的「美化 URL」能力；而目标平台没有这个默认能力、也没有开关【文档】。押注平台特性等于给换平台埋断链。

**尾斜杠**：站内链接统一带。但**不要相信** `trailingSlash: 'always'` 能锁死线上唯一写法——纯静态站的尾斜杠由托管平台决定，Astro 管不了【文档】。这条是已移交的风险，见 §16 A1。

### 3.3 slug：手填、格式锁死、发布后不可变

**URL 是本项目唯一会跨出仓库、被别人复制走的产物。** 标题、字段名、目录结构都能随便改，代价是一堆 diff；URL 一改，简历、邮件、别人论文致谢里的链接全部失效。所以：

1. **必填**，写在 frontmatter 里。没写 = 构建失败（四个集合都靠 schema 保证）。
2. **格式**：`^[a-z0-9]+(-[a-z0-9]+)*$`——全小写、连字符分隔、不许下划线、不许首尾或连续连字符。
3. **集合内唯一**。两个目录写同一个 slug 时，构建**必须**失败（见 §8.1）。
4. **发布即不可变**：改 slug 等于发一篇新内容。静态站没有重定向能力，就先不许诺自动跳转。
5. **目录名 = slug**。文件名与 URL 对不上时，构建**必须**失败（见 §8.2）。

> ⚠️ **第 5 条目前只有论文集合有执行力**：预检（§8.2）是为论文写的，项目与分享还没有对应的一致性检查。它们的施工票要么复用同一个预检，要么把检查抽成对三个集合通用的一个函数——**别让「必须失败」变成一句空话**。这条登记在 §16 D3。

**不要用「英文标题自动转」**：英文标题是内容，会变（拼写修正、改投会议、副标题增删）。让 URL 从会变的东西派生，等于把不可逆的成本挂在可变的东西上。

**英文标题没思路时的兜底**：`<会议简称><年份>-<两三个关键词>`，例如 `cvpr2026-few-shot-seg`。

**slug 不是 `title_en` 的转写**：`title_en` 是 `Deep Residual Learning for Image Recognition`，slug 是 `deep-residual-learning`。slug 只要短、唯一、稳定。

### 3.4 中文与 DOI 都不进 URL

**中文不进 URL**：中文进路径会被百分号编码，复制粘贴变丑、邮件里容易截断；而且构建产物目录名是中文原样、浏览器地址栏是编码形态，同一篇文章有两个字面形态。

**DOI 不进 URL**（这个方案被明确否决过，理由记在这里免得下次又想）：

- **范畴错误**：DOI 标识的是「某一次寄存」，不是「这篇论文」。同一篇论文常有多个 DOI——arXiv 预印本一个、正式发表后期刊再发一个。用 DOI 求稳定，结果 DOI 自己就会变一次。
- DOI 按定义带斜杠【文档】，必然让路径变多段；DOI **大小写不敏感**【文档】而文件系统大小写敏感，两个写法在 DOI 世界是同一个、在 `dist/` 里是两个目录。
- **不是每篇都有**：workshop 论文、在投稿件、部分中文期刊、学位论文都可能没有 DOI。既然「没有 DOI」必须兜底，slug 规则无论如何省不掉。

DOI 仍然要存，但它是**内容字段**，不是 URL 的一部分（见 §5.1）。

### 3.5 栏目段名与不做的事

- 段名固定三个：`papers` / `projects` / `notes`。详情 URL **不带年份、不带分类层级**——年份是可变的元数据，进 URL 就让 URL 随元数据漂移。
- **不分页，也不预留** `/page/2/`。十几二十条内容滚动就够了；真超过 50 条再加，届时用 `[...page].astro` 才能让第 1 页留在 `/papers/`【文档】。

## 4. 内容模型总则

### 4.1 一条判据：schema 只管结构不变量，不管编辑品味

| schema 该管（写错页面就是坏的） | schema 不该管（写错只是编得不好） |
| --- | --- |
| slug 格式、必填字段缺失、图片路径不存在、替代文字缺失、`me: true` 数量、日期必须带日 | 「一个项目配几张图好看」「摘要该多长」「正文写几段」 |

用硬失败去表达编辑偏好，是拿最重的工具干最轻的活。所以：**配图张数不设上限**（`min(1)` 就够），**正文段落数不做强制**（2–5 段只是写作建议）。

### 4.2 字段命名全 `snake_case`

不用 camelCase。混用的真实代价不是审美：`data.titleEN` 拼错得到 `undefined`，Astro 渲染成空字符串，**构建照样成功**——又一次静默失效。

### 4.3 一篇一个目录

```
src/content/<集合>/<slug>/
├── index.md          frontmatter + 正文
└── fig-1.webp        图放在它旁边
```

判据不是「哪个好看」，是**删除的安全性**：删内容 = 删一个目录，图不会变成孤儿。统一放一个大目录时，删 `.md` 会留下一堆没人引用的图，而没有任何工具会报错。

附带好处：`./fig-1.webp` 这种相对路径的基准**就是条目文件所在目录**，frontmatter 里的 `image()` 与正文里的 `![](./fig-1.webp)` 语义完全一致【文档】——一套心智模型管两处。

**`index.md` 不要与同名 `.md` 并存**：`papers/<slug>.md` 与 `papers/<slug>/index.md` 会撞同一个条目 id。loader 用 `pattern: '**/index.md'` 从根上不收根目录散落的 `.md`，但**它挡不住手填 slug 撞车**——那道防线在 §8.1。

### 4.4 图片一律放 `src/`，不放 `public/`

`src/` 的图构建期会转码、自动补宽高；`public/` 的图**永不优化**，而且图片字段**不接受** `public/` 路径——写了直接 `ImageNotFound` 构建失败【实测】。

### 4.5 图片字段的三件套（`figures` / `shots` 共用，不再重复讲）

两个集合的图片字段形状相同，规则只有这三条。**下面 §5 的字段表与样例都只引用这一节，不再各写一遍**：

```yaml
- src: ./fig-1.webp        # 相对路径，基准是条目文件所在目录
  caption: 中文图注          # 论文用 caption；项目用 alt，名字不同、作用相同
```

| 规则 | 说明 |
| --- | --- |
| **至少一张、不设上限** | `min(1)` 是结构不变量（一张都没有，封面就取不到）；张数是编辑品味，不设上限 |
| **第一张即封面** | 首页取 `[0]`，详情页全列。所以别把「图 5」放第一 |
| **每张必须有说明文字** | 论文的 `caption`、项目的 `alt` 是**同一个位置**的两种叫法，都兼作图片的替代文字。缺了等于对外无障碍失守，而 `<Image />` 的 `alt` 缺失本身就是构建错误【文档】 |

**为什么用对象数组而不是两个平行数组**（`figures` + `figureCaptions`）：平行数组是经典陷阱——两张图配三句说明能通过校验，然后模板把错位的文字配到错位的图上，**构建不报错**。

**宽高不要手填**：`image()` 在构建期返回 `ImageMetadata`，宽高自动带上【文档】。

## 5. 四个集合的字段契约

> 每个集合给三样：字段表（含「照着填」的一列）、一份完整可抄的 `index.md`、以及「这个集合写错会怎样」。
>
> 表格里「必填」为「是」的字段，缺了构建直接失败，报错会指出是哪个字段。

### 5.1 论文 `papers`

**目录**：`src/content/papers/<slug>/index.md`（配图放同目录）

| 字段 | 必填 | 类型与约束 | 为什么存在 | 照着填 |
| --- | --- | --- | --- | --- |
| `slug` | 是 | 字符串，`^[a-z0-9]+(-[a-z0-9]+)*$`，集合内唯一，必须等于目录名 | URL 段，发布后不可变 | `attention-is-all-you-need` |
| `title_en` | 是 | 非空字符串 | 英文原名。详情页在中文标题下方小字显示，首页与列表页当次要行 | `"Attention Is All You Need"` |
| `title_zh` | 是 | 非空字符串 | 中文主标题，详情页 H1 | `注意力机制就是你所需要的一切` |
| `year` | 是 | 整数 1990–2100 | 排序第一级；与 `venue` 同行渲染 | `2017` |
| `month` | 是 | 整数 1–12 | 排序第二级（同年多篇要有确定的先后） | `6` |
| `venue` | 是 | 非空字符串，形态 `会议名 年份`（如 `CVPR 2016`） | 只渲染它一项（不再拼 `year`）——它已含年份。**这一条修正了源裁定的自相矛盾，见 §0.5 第 2 条** | `NeurIPS 2017` |
| `authors` | 是 | `array<{ name: 非空字符串, me?: 布尔 }>`，至少 1 人；按原文顺序 | 渲染作者行；`me` 驱动加粗与徽标 | `- name: Kaiming He`（普通作者）／`- name: Wenxuan Zhang` 换行缩进 `me: true`（你自己，全篇只一次） |
| `my_role` | 是 | 枚举 `first` / `co-first` / `corresponding` / `coauthor` | 只记录「你在这篇里的角色」，据此决定徽标。不给每位作者加标记 | `coauthor` |
| `summary` | 是 | 字符串，40–400 字，多段用 `\|-` | 详情页中文简介（1–2 段）。放 frontmatter 才能白拿长度校验 | `summary: \|-` 下一行开始写第一段，空一行写第二段（见下方样例 A） |
| `doi` | 否 | **裸 DOI**，`^10\.\d{4,9}/\S+$` | 模板拼 `https://doi.org/` + 裸值 出「查看原文」 | `10.1109/CVPR.2016.90` |
| `code_url` | 否 | URL | 有代码时渲染链接 | `https://github.com/KaimingHe/deep-residual-networks` |
| `figures` | 是 | `array<{ src: image, caption: 非空字符串 }>`，至少 1 张、不设上限（**三件套见 §4.5**） | 详情页全列，首页取第一张；`caption` 兼作替代文字 | `- src: ./fig-1.webp` 换行缩进 `caption: 残差学习的基本单元：输入 x 经两层卷积后与恒等捷径相加，再经 ReLU 输出。` |

**跨字段约束**：`authors` 里 `me: true` **恰好出现一次**。0 次或 2 次都构建失败。

**为什么 `me` 要显式写，而不是用全局配置里的姓名去匹配**：若用 `owner: "Wenxuan Zhang"` 去比对字符串数组，那 `Zhang Wenxuan`、`W. Zhang`、带逗号的变体都会匹配失败，**构建不报错**，只是页面上你的名字不加粗——要等人肉看页面才发现。显式标记把这件事从「运行时猜」变成「构建时校验」。

**为什么只有 `my_role` 而没有「每位作者是不是共一」**：页面只宣传你，读者不需要知道别人是不是共一。

**为什么不设录用率**：它是**范畴错误**——描述的是会议而不是这篇论文，同一会议不同年份的值还不同，官方常不公布精确数字、第三方口径不一，每加一篇都要重查。要表达含金量应标录用形式（`Oral` / `Spotlight`），那是这篇论文自己的待遇；本轮不设。

**为什么不设 BibTeX 字段**：手写就会与 `authors`/`venue`/`year` 重复表达同一事实，两处迟早不一致。它应由字段**生成**，不是存原文。

**年份口径**：`year` 填**正式发表年**。未正式发表时填 arXiv 首次公开年、`venue` 写 `arXiv`。

#### 渲染契约（模板照此实现）

- **详情页**：H1 = `title_zh`，紧随其后一行 `title_en`（小字、次要色）。
- **元信息行**：只渲染 `venue`（它已含年份）。**不要**再拼 `· year`——那会渲染成「CVPR 2016 · 2016」。
- **作者行**：`authors` 用 `、` 连接；`me: true` 的那一位加粗，并在其名后追加角色徽标——`first` → 「第一作者」、`co-first` → 「共同一作」、`corresponding` → 「通讯作者」、`coauthor` → 无徽标。
- **简介**：`summary` 按填写的分段渲染（`|-` 保住的换行要真的换行）。
- **图**：`<Image src={fig.src} alt={fig.caption} />` + `<figcaption>{fig.caption}</figcaption>`。宽高由构建期自动提供，**模板不手填**。
- **DOI**：存在时渲染 `<a href={"https://doi.org/" + doi}>查看原文</a>`；**模板负责拼前缀，内容里绝不存链接**。
- **代码仓库**：`code_url` 存在时渲染链接；不存在则整项不出现（不渲染空 `href`、不灰化）。
- **列表页**：骨架期按首页同构——`title_zh` 为主、`title_en` 小字为辅（列表页的主次是留给以后的展示决定，见 §16 C5）。

### 5.2 项目 `projects`

**目录**：`src/content/projects/<slug>/index.md`（截图放同目录）

| 字段 | 必填 | 类型与约束 | 为什么存在 | 照着填 |
| --- | --- | --- | --- | --- |
| `slug` | 是 | 同论文：正则、集合内唯一、等于目录名 | URL 段 | `paper-digest` |
| `name` | 是 | 非空字符串 | 卡片标题 | `Paper Digest` |
| `summary` | 是 | 非空字符串，**一句话** | 首页与列表页只显示它，缺了无法排版 | `把 arXiv 新投稿按研究方向筛一遍，省掉每天早上翻列表的时间。` |
| `date` | 是 | 日期，**必须带日**（`YYYY-MM-DD`） | 排序依据 + 列表显示。写成 `2026-05` 会被「补成 5 月 1 日」，所以必须拦住 | `2026-05-18` |
| `stack` | 是 | `array<非空字符串>`，至少 1 项；元素写**产品原名大小写** | 详情页技术栈行 | `[Python, FastAPI, SQLite, Preact]` |
| `shots` | 是 | `array<{ src: image, alt: 非空字符串 }>`，至少 1 张、不设上限（**三件套见 §4.5**） | 详情页按填写顺序全列；`alt` 必填 | `- src: ./shot-1.webp` 换行缩进 `alt: 首页列表，每行一条论文，左侧是方向标签` |
| `repo` | 否 | URL | 有仓库时渲染链接 | `https://github.com/zwxdogs/paper-digest` |
| `demo` | 否 | URL | 有演示地址时渲染链接 | `https://demo.example.com` |
| 正文 | 是 | Markdown，非空 | **「为什么做这个」**——项目条目不可替代的两样之一是截图，另一样就是它。2–5 段是写作建议，不做强制 | `---` 之后空一行开始写，段落之间空一行（见下方样例） |

**不做**活跃 / 归档状态字段：那是编辑品味，而且一旦有 `status`，首页与列表页就多一条「要不要过滤」的分支，分支漂移不报错。

**日期为什么用 `date` 而不是 `year`+`month`**：项目的「什么时候做的」读者只关心大致先后，一个日期字段就够。但它**必须带日**——写成 `2026-05` 会被日期解析补成 5 月 1 日，静默变成一天。所以 schema 只接受完整日期，见 §5.5 的日期写法。

### 5.3 分享 `notes`

**目录**：`src/content/notes/<slug>/index.md`

| 字段 | 必填 | 类型与约束 | 为什么存在 | 照着填 |
| --- | --- | --- | --- | --- |
| `slug` | 是 | 同论文：正则、集合内唯一、等于目录名 | URL 段 | `first-week-with-a-new-keyboard` |
| `title` | 是 | 非空字符串 | 列表页与详情页唯一的标题 | `换了一块键盘，以及我为什么终于认了` |
| `date` | 是 | 日期，**必须带日** | 排序依据 + 列表显示 | `2026-11-16` |
| 正文 | 是 | Markdown，非空 | 分享条目不可替代的两样是时间 + 一段话，其余都是装饰 | `---` 之后空一行开始写；正文第一段就是页面的描述来源（见 §10） |

**不设** `summary`：摘要只在需要时从正文首段自动截取（见 §10），用于页面的描述元信息。首页与列表页只显示「标题 + 日期」，不显示摘要——这是「不设 `summary`」能成立的前提。

**不设** `tags`：标签的价值在能聚合，而现在明确不做标签归档页；只贴标签不给归档入口，等于给读者一个点不动的线索。

**不设** `draft`：草稿状态意味着「有内容但不该发布」，而内容在仓库里、提交即发布——真要留着不发，就不要提交。

文件：`src/content/notes/why-i-write-this-site/index.md`

```markdown
---
slug: why-i-write-this-site
title: 为什么我还是决定自己写一个主页
date: 2026-11-02
---

成果散在 arXiv、GitHub、几个 PDF 和三五个聊天窗口里。别人问「你有没有主页」，我只能临时发几条链接；导师想一次看全我发过什么，得自己拼。
```

#### 分享线的特殊之处：骨架期它是空的

空内容意味着它的详情页模板**一次都不会被执行**【实测】。`getStaticPaths()` 返回 `[]` 时，组件函数体（含整个模板）执行 0 次——模板写错了也全绿。

后果：错误会**推迟到第一篇文章进来的那一刻**才爆发，而那时你正处在「加内容」的心智状态下，遇到一个「模板写错了」的报错，归因成本极高。

所以分享详情页必须写，但它的验证方式完全不同：**往返验证**（见 §14.1 断言六）。这是唯一能证明该模板没写错的手段。

| 字段 | 必填 | 类型与约束 | 为什么存在 | 照着填 |
| --- | --- | --- | --- | --- |
| `slug` | 是 | 字面量 `profile` | **钉死条目身份**。本机实测：不写这个字段时条目 id 是 `index`，写了才是 `profile`【实测】 | `profile` |
| `name` | 是 | 非空字符串 | 页面上你的名字 | `Wenxuan Zhang` |
| `email` | 是 | 邮箱格式 | 联系方式栏第一项 | `wenxuan@example.com` |
| `github` | 否 | URL | 有就渲染，没有整项不出现 | `https://github.com/zwxdogs` |
| `scholar` | 否 | URL | 有就渲染，没有整项不出现（与 `github` 同规则） | `https://scholar.google.com/citations?user=xxxx` |
| 正文 | 是 | Markdown，非空 | **自我介绍那一段**。改它要改 Markdown 而不是 TypeScript——这是它不放进 `consts.ts` 的全部理由 | `---` 之后空一行开始写，2–3 段（见下方样例） |

**不加 ORCID**：三项联系方式已经是「够用」的边界，第四项只会让「缺了整项不渲染」这条规则多一个实例，没有新价值。

**缺的项整项不渲染，不做灰化**：灰掉的链接不可点，读者会以为坏了；而「灰化」需要禁用态的视觉规范，属「完整视觉设计」，不在本轮。写错 → 构建失败；没写 → 合法不显示。两种情况不混。

**这一栏出现两次**（介绍下方 + 页脚），必须是同一个组件渲染同一份数据，不许两处各写一遍。

#### 这个集合写错会怎样

| 你写错的事 | 结果 |
| --- | --- |
| 整个文件不存在 | 首页构建失败并明确报错（不静默渲染空白页） |
| `slug` 不写或写成别的 | 构建失败（字面量校验） |

| `github` / `scholar` 不写 | **合法**，整项不出现 |

### 5.5 日期怎么写（`projects` 与 `notes` 共用）

**只接受完整日期**：`2026-05-18`。这条比看起来重要：

- `date: 2026-05-18` 不加引号时，会被 YAML 层解析成 **`Date` 对象**而不是字符串【实测】。
- `date: 2026-05`（只写年月）会被解析成**字符串** `"2026-05"`【实测】，而 `z.coerce.date()` 会把它**悄悄补成 2026 年 5 月 1 日**，构建成功、日期错了【实测】。
- 因此 schema **不能用** `z.coerce.date()`；要用一个只认「完整日期」的收窄写法：字符串形态必须是 `^\d{4}-\d{2}-\d{2}$`，否则直接给 `Date` 类型校验，报「expected date, received string」【实测】。

**排序与显示**：内部拿到的是 `Date` 对象，排序比较 `date.valueOf()`，显示用 `YYYY-MM-DD`。

**收窄写法**（放 `src/content.config.ts`，`projects` 与 `notes` 共用同一个）：

```ts
import { z } from 'astro/zod';

// 只接受「必须带日」的日期。
// 为什么不能直接用 z.coerce.date()：它会把 "2026-05" 补成 2026-05-01，构建成功但日期错了。
// 这里的做法是——字符串必须长得像 YYYY-MM-DD，否则原样交给 z.date() 去拒绝。
const fullDate = z.preprocess(
  (v) => (typeof v === 'string' && /^\d{4}-\d{2}-\d{2}$/.test(v) ? new Date(`${v}T00:00:00Z`) : v),
  z.date(),
);
```

【实测】三种输入的结果：`2026-05-18`（不带引号，YAML 已解析成 `Date`）→ 通过；`"2026-05-18"`（带引号，字符串）→ 通过；`2026-05` → 失败，报 `expected date, received string`。

> 写成 `new Date(\`${v}T00:00:00Z\`)` 而不是 `new Date(v)`：后者在部分运行时按本地时区解析，会让「同一天的日期」在不同机器上差一天。

## 6. 排序：比较器必须把每一级键写全

### 6.1 唯一真相在 `src/lib/collections.ts`

```ts
export const HOME_LIMIT = 3;

// 论文：year 降序 → month 降序 → slug 升序
// 项目 / 分享：date 降序 → slug 升序
```

**首页与三个列表页只调这一组函数**，不各自再写一遍 `.sort()`。两处各写一遍迟早漂移，而漂移**不报错**，只让首页和列表页的顺序不一致——没人会发现，直到有人问「为什么首页第一篇不是列表页第一篇」。

### 6.2 为什么每一级键都要写

`Array.prototype.sort` 自 ES2019 起规范强制稳定【文档】，所以「靠稳定性保住第二级」在单次排序内成立——**但稳定性只保住「进 `sort()` 那一刻」的次序**，而那个次序来自 `getCollection()`，**它没有顺序契约**（官方原话是 non-deterministic and platform-dependent）【文档】。

⇒ 比较器自己写完每一级键。`slug` 强制唯一（§3.3），所以永远有全序，不存在完全相等的并列。

⇒ **分享也要第三级**：同一天两篇，没有第三级就退化成依赖输入顺序。

### 6.3 排序里用的「slug」就是 `entry.id`

frontmatter 的 `slug` 会**覆盖**自动生成的条目 id【文档 + 实测】（这也正是 §5.4 里 `slug: profile` 能让 id 变成 `profile` 的原因）。所以**比较器里一律用 `entry.id`，不要写 `entry.slug`**（那个属性在 Astro 7 已不存在）。

⚠️ **「目录名 = slug = id」三者恒等，目前只有论文集合被预检强制**（§8.2）。项目和分享是「slug = id」成立、但「目录名 = slug」没有检查——所以对它们来说，用 `id` 排序是对的，但别以为目录名写错会报错（见 §16 D3）。

## 7. 首页：不是第二个列表页，是橱窗

### 7.1 结构与取数

从上到下四段：**个人介绍 → 论文 → 项目 → 分享**。每段每条只承担一个职责——让人判断要不要点开。

| 栏 | 显示 | 留到点开之后 |
| --- | --- | --- |
| 论文 | 封面图（`figures[0]`）+ `title_zh`（主）+ `title_en`（次，小字）+ `venue`（已含年份，不再拼 `year`） | `summary`、`authors`、`doi`、`my_role` |
| 项目 | 封面图（`shots[0]`）+ `name` + `summary` | `stack`、`repo`/`demo`、动机正文 |
| 分享 | `title` + `date` | 正文 |

论文的 `summary` **不进首页**：40–400 字在三张卡里会撑爆首屏。项目的 `summary` 要留：一句话简介就是为这个钩子设计的。

### 7.2 三档降级

| 该栏条目数 | 渲染 |
| --- | --- |
| `0` | `暂无{栏目名}。` → `暂无论文。` / `暂无项目。` / `暂无分享。` |
| `1 … 2` | 正常渲染这几条，**不补占位、不留白、不重复** |
| `≥ 3` | 取前 3 |

**中间档不补占位是刻意的**：「只有一个项目」不是错误状态，补一句「还有更多」反而是假话。

**空态文案只有一个来源**：`暂无{栏目名}。` 这句话由 `src/components/EmptyState.astro` 渲染，三张列表页与首页三栏共用。不要写「敬请期待」之类——内容一填进来就成死文本，还得记得删。

**为什么是 3 条**：地图终点的验收是骨架里真的填进 2 篇论文 + 1 个项目。取 2 条，论文栏刚好填满，「不足 N 条」那条分支在骨架期**永远不触发**；取 3 条，骨架当场把「只有 1 个项目」渲染一遍。三栏统一而非分别定：一个常量，改一处三栏一起变。

### 7.3 「查看全部 →」条件显示

**仅在该栏总条数 > 3 时显示。** 链接的价值等于「用户想看的第 4 条是否存在」：只有 3 条时挂「查看全部」，点进去还是这 3 条，那才是真冗余；一旦有第 4 篇就需要出口，而人肉记「什么时候加这个链接」不可能。

### 7.4 不做置顶

没有 `featured`、没有手动排序字段。做了，首页显示了什么就不能从内容文件推出来，得读额外字段；那字段写错**不报错**、只是顺序不对——又一枚静默失效点。

不做，规则压成一句：**首页严格等于各集合既定排序的前 3 条**。想让某篇更靠前，把 `year` / `month` 填对。

## 8. 两道防静默失效的防线

### 8.1 第一道：构建配置层，重复 slug 从静默变成硬失败

`astro.config.mjs`：

```js
export default defineConfig({
  prerenderConflictBehavior: 'error',
});
```

**为什么必须有这一行**：默认值是 `'warn'`——两个条目撞同一个 slug 时只打一条警告，**构建成功**，`getCollection()` 里只剩一条，**且谁被覆盖没有契约**。

【实测】两个目录 `dir-a` / `dir-b` 都写 `slug: dup-probe`：

| 配置 | 结果 |
| --- | --- |
| 默认（`'warn'`） | 构建成功，退出码 0，只留下 `dir-b`，另一篇静默消失（本机这次留下的是 `dir-b`——**谁胜出没有契约**，换台机器或换次构建可能反过来） |
| `'error'` | `[DuplicateContentEntrySlugError] papers contains multiple entries with the same slug: 'dup-probe'`，**退出码非零**（本机是 `-1073740791`） |

**注意退出码**：失败时它不等于 1。任何脚本都只能断言「非零」，不能断言「等于 1」。

**这条的可靠性**：`glob()` 复用 `prerenderConflictBehavior` 处理重复条目 slug，这件事**只在源码里体现、官方文档未写明**【源码】——所以它进了 §14 的升级复核清单。

### 8.2 第二道：构建期预检

文件名（目录名）与 URL 对不上时，URL 仍按 frontmatter 的 `slug` 生成、页面正常，只是磁盘目录名与 URL 不符——半年后没人看得懂。跨条目唯一性官方零承诺（schema 逐条校验，拿不到其它条目）。

所以有一个预检，管三件事，放在 `src/lib/papers-preflight.ts`：

1. **目录名必须等于 `slug`**（从 `entry.filePath` 推导目录名【实测：`filePath` 确实存在】）；
2. **slug 集合内唯一**；
3. **DOI 不能跨条目重复**（大小写不敏感比较）。

**调用点：论文列表页与论文详情页的取数入口各调一次。** 两处都调，任一路由单独构建也能拦住。

**为什么是「两处都调」而不是「一处调就够」**：静态生成器会把每个路由单独跑一遍，只在一处调，另一处单独构建时就没有防线。

> 项目与分享目前只有 §8.1 那道防线 + schema。要不要给它们也加目录名一致性预检，是它们各自的施工裁定，本稿不新增。

### 8.3 完整 schema 的写法要点

`src/content.config.ts` 里四个集合都用 `glob()` loader + `pattern: '**/index.md'`。要写对的几处：

- 论文的 `authors` 用 `.refine()` 保证 `me: true` 恰好一次。
- 图片字段按 §4.5 的三条规则写（对象数组、`.min(1)`、无上限）。
- `image()` 只接受条目目录内的相对路径，不接受 `public/` 或 `https://`【实测】。
- 日期用 §5.5 的收窄写法，不用 `z.coerce.date()`（理由见 §0.5 修正 1）。
- **正文（「为什么做这个」、自我介绍、分享正文）schema 读不到**，只能靠构建期预检或在页面里断言非空。这条要在落地时明确归属，否则「正文为空」会静默通过。

## 9. 图片

### 9.1 存放与引用

- 一律放**条目目录内**：`src/content/papers/<slug>/fig-1.webp`。
- frontmatter 里写相对路径：`src: ./fig-1.webp`。
- 正文里插图同理：`![](./fig-1.webp)`——路径基准是条目文件所在目录【文档】。
- 封面、说明文字、宽高三条规则见 **§4.5**，不再重复。

### 9.2 提交前压缩（一次性手动步骤，不做自动化流水线）

| 项 | 阈值 |
| --- | --- |
| 长边 | **≤ 1600 px** |
| 格式 | **`.webp`** |
| 单张体积 | **≤ 300 KB** |

**一条命令搞定**（本机实测通过，`sharp-cli` 5.3.0，不需要把它变成项目依赖）：

```powershell
npx --yes sharp-cli@5 resize 1600 1600 --fit inside --withoutEnlargement -q 82 -i 原图.png -o fig-1.webp
```

- `1600 1600 --fit inside` = 按长边缩到 1600，短边等比，不裁切。
- `--withoutEnlargement` = 小图不会被放大。
- `-o` 的**扩展名决定输出格式**，写成 `.webp` 就是 webp。
- 【实测】2400×1200 的图 → `1600x800 webp`；1000×2400 的图 → `667x1600 webp`（长边都落在 1600）。

**检查一条内容里的图**（可选，用 Astro 自带的 `sharp`，不加新依赖）：

```js
// 存成 scripts/img-check.mjs 后：node scripts/img-check.mjs src/content/papers/xxx/*.webp
import sharp from 'sharp';
import { statSync } from 'node:fs';
for (const f of process.argv.slice(2)) {
  const m = await sharp(f).metadata();
  const kb = Math.round(statSync(f).size / 1024);
  const ok = Math.max(m.width, m.height) <= 1600 && m.format === 'webp' && kb <= 300;
  console.log(ok ? '✓' : '✗', f, `${m.width}x${m.height}`, m.format, `${kb}KB`);
}
```

```powershell
Get-ChildItem src/content/papers/*/*.webp | Select-Object Name, @{n='KB';e={[int]($_.Length/1KB)}}
```

**为什么阈值不是「张数上限」**：张数是编辑品味，体积是真实约束——它决定访客在手机流量下多久看到图。

**为什么不进自动化流水线**：整个仓库只有 4–5 张图，为它建流水线要多一个常驻依赖和一套构建钩子，成本远大于收益。代价是**它会漂**——见 §16 C1。

## 10. 分享的页面描述：从正文首段自动截取

用途**只有一个**：`<meta name="description">`。首页与列表页不显示摘要。

输入是 Markdown 原文（`entry.body`，即磁盘上未被改写的文本），处理顺序：

1. 按空行切块；
2. **跳过**纯图片块（整块就是一个 `![](...)`）与标题块（`^#{1,6}\s`）；
3. 取第一个可用块；
4. 剥标记：`![alt](url)` 整段删掉；`[text](url)` → `text`；`**x**` / `*x*` / `` `x` `` → `x`；合并连续空白；
5. 截到约 100 个字符（中文按字符计），加 `…`；
6. **没有可用块就返回空串，调用方整项省略 `<meta name="description">`**——不输出空标签。

**不能简单 `slice(0, 100)`**：`entry.body` 是磁盘原文，图片语法没被改写，前 100 个字符很可能是一串 `![](…)`。

官方**没有**摘要 API（`render()` 只返回 `Content` / `headings` / `remarkPluginFrontmatter`）【文档】，所以这条属社区做法、无契约——已进风险表。

## 11. 样式：最简，但必须可测量

**一份**全局样式 `src/styles/global.css`，**只用 4 个 CSS 变量**：

| 变量 | 值 | 管什么 |
| --- | --- | --- |
| `--color-text` | `#1a1a1a` | 文字色 |
| `--color-bg` | `#ffffff` | 背景色 |
| `--max-width` | `42rem` | 正文最大宽度 |
| `--line-height` | `1.7` | 行高 |

三条硬约束：

1. **320 / 768 / 1440 三档宽度无横向滚动。** 防线是 `body { max-width: var(--max-width) }` + `html { overflow-wrap: break-word }` + `img { max-width: 100%; height: auto }`。
2. **不引任何 CSS 框架。**
3. **不引任何外部字体**（只用系统字体栈）。

**为什么不写「零 CSS」**：完全不写 CSS 的问题不是难看，是**让验收无法执行**——浏览器默认样式下「移动端不溢出」根本量不出来（中文长句不换行就横向滚动）。

**为什么不做完整视觉设计**：配色体系、字体选择、组件外观是下一个 effort 的事；本轮只保证「能读、量得出来」。

**焦点可见**：`a:focus-visible` 必须有可见轮廓。只用键盘也要走得完全站，并且看得见焦点在哪。

## 13. 新增一条内容的操作步骤

以**加一篇论文**为例，从零走到提交。项目和分享同理，差别只在字段与图的数量。

### 第 1 步：想好 slug

- 全小写、连字符分隔、只含 `[a-z0-9-]`。
- 它会是 URL 的一部分，**发布后不能改**。
- 短、唯一、稳定。从英文标题里挑两三个关键词：`deep-residual-learning`，不是 `deep-residual-learning-for-image-recognition-2016`。

### 第 2 步：建目录

```powershell
New-Item -ItemType Directory src/content/papers/deep-residual-learning
```

目录名**必须**与 `slug` 完全一致，否则构建失败。

### 第 3 步：准备配图

1. 从论文 PDF 里截原图（不是自画示意图——原图注本就是给这图做说明的）。
2. 压缩到阈值内：

```powershell
npx --yes sharp-cli@5 resize 1600 1600 --fit inside --withoutEnlargement -q 82 -i .\下载\fig1.png -o src/content/papers/deep-residual-learning/fig-1.webp
```

## 14. 验收怎么跑

分三组：**1 条自动命令 + 2 条人工 + 5 条人眼**。能靠退出码或文件存在性判的全自动，其余压到 10 条以内。

### 14.1 自动：`npm run verify`（8 条断言）

一条命令。它自己先跑 `npm run build`，然后在 `dist/` 上做断言；**不需要你手动先构建**。

| # | 断言 | 抓什么故障 |
| --- | --- | --- |
| 1 | 构建进程**退出码非零即失败**（不断言「等于 1」：本机实测失败时是 `-1073740791` / `0xC0000409`） | 构建失败 |
| 2 | 构建输出里**不出现** `[ERROR]` | 渲染错误被淹没在日志里 |
| 3 | **警告走白名单**：允许「空集合那两条」，**禁止**出现 `The base directory ... does not exist`（它说明占位文件丢了） | 集合目录/占位文件丢失 |
| 4 | 8 条路由对应的产物文件**逐个存在** | 路由没生成 |
| 5 | `dist/notes/` 下**没有**详情子目录（0 条内容时不该生成） | 空集合生成了假页面 |
| 6 | **分享详情页往返验证**：临时塞 1 条 → 断言该条真实标题出现在产物里 → 删除 → 再构建干净（退出码 0、`dist/notes/` 只剩列表页） | **模板写错但构建通过**（唯一手段） |
| 7 | **内部断链**：扫全部 `dist/**/*.html` 的链接与资源引用，逐个断言目标存在 | 链接写错、内容删了但链接还在 |
| 8 | **图片**：页面里 `<img>` 数量达到下限（≥ 4），且引用的源文件确实存在于内容目录 | 图裂了、图被误删 |

**第 3 条为什么是白名单而不是「警告为零」**：「警告为零」是**永远打不上的勾**。空集合有两类警告消不掉：

- `[glob-loader] No files found matching "**/index.md" in directory "src\content\<集合>"`（目录存在但空）
- `[content] The collection "<集合>" does not exist or is empty.`（这条与内容无关，无论如何都在）

【实测】清空 `dist/` 与 `.astro/` 冷构建、四个集合全空时，构建输出里有 8 条 `[WARN]`（4 条 glob-loader + 4 条 content），退出码 0。而把 `src/content/notes/` 整个移走，警告会变成更差的 `The base directory "E:\项目\MyWeb\src\content\notes\" does not exist.`【实测】——所以 `.gitkeep` 必须有，它的作用是**防新克隆退化**，不是消警告（空目录不被 git 跟踪，clone 后消失）。

**第 6 条为什么是唯一手段**：见 §5.3。空集合时该模板执行 0 次，构建对它零信息。

**落地形态**：`.gitkeep` 与警告白名单都做成**仓库里的实体文件**，不写成文档里的一句约定——约定会漂移，文件不会。脚本用 Node 原生能力手写（`scripts/verify.mjs`），**不引测试框架**：这 8 条断言都不需要框架，多一个常驻依赖就多一处要维护的东西。

**将来有人在 `notes` 里加内容时**：警告自然消失，白名单那条不再匹配，脚本不会因此误报。

| # | 怎么跑 | 看什么 |

### 14.3 人眼（5 条，压到最短）

**当前构建的 8 条警告**（供 #15 写白名单时对照，见 §14.1 第 3 条）：清空 `dist/` 与 `.astro/` 后冷构建，全部 `[WARN]` 恰好 8 条——4 条 `[glob-loader] No files found matching "**/index.md" in directory "src\content\<集合>"`（四个集合各一条），加 4 条 `[content] The collection "<集合>" does not exist or is empty.`（实测这次是 `notes`×2、`projects`×2）。

⚠️ **`[content]` 那条的出现次数与顺序不能按「谁取了数」推导**：同一次构建里 `/papers/` 与首页都取过 `papers`、却一条都没出，而 `notes` 与 `projects` 各出了两次。所以白名单**必须按模式匹配**（认前缀与集合名），**不要按条数、不要按出现顺序**——按条数写成的断言会随页面数量、渲染顺序变化而误报。写完后重跑一次冷构建核对实际条数。

## 18. 术语与决策来源

### 18.1 术语

| 词 | 在这个项目里指什么 |
| --- | --- |
| 集合 | 一类内容（论文 / 项目 / 分享 / 个人介绍），对应 `src/content/<集合>/` |
| 条目 | 集合里的一条，对应一个 `<slug>/index.md` |
| 条目目录 | `src/content/<集合>/<slug>/`——删内容就删它 |
| slug | 条目目录名 = frontmatter 的 `slug` = URL 段，三者恒等 |
| 封面 | 一个条目的第一张图（`figures[0]` / `shots[0]`），首页用它 |
| 预检 | 构建期跑的一致性检查（§8.2），写错就构建失败 |
| 接缝 | 唯一被验证的外部界面——本项目是 `npm run verify` 跑在 `dist/` 上 |
| 往返验证 | 临时塞一条内容 → 断言它进了产物 → 删掉 → 再构建干净。用于验证空集合时不会被执行到的模板 |
| 白名单 | 允许出现的警告清单。不是「警告为零」——那是永远打不上的勾 |
| **探索票** | 规划阶段「先把事情想清楚」的票，只产出裁定，不写代码。地图 #1 下的 6 张（#2–#7）都是探索票，全部已关闭 |
| **实施票** | 施工阶段「把裁定落地」的票，产出代码与内容。规格 #8 下的 7 张（#9–#15）都是实施票 |
| **骨架期** | 本轮（规格 #8）的整个期间。特征是：结构先立起来、内容只填「够证明字段够用」的量（2 篇论文 + 1 个项目），分享栏是空的 |
| **落点** | 某个结论最后落在仓库的哪个文件、或哪张票上。「这条的落点是 `docs/design/站点设计稿.md`」 |
| **移交** | 本轮决定不做、但必须让下一轮知道的事。§16 整节就是移交清单 |
