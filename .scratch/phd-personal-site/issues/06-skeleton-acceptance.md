## Question

本图的终点是「设计文档 + 能跑的最小骨架」。要把「怎么算跑通」定成可以逐条打勾的标准，否则骨架会一直处于「好像差不多了」的状态。

1. **骨架必须包含什么**：4 个页面（首页/论文/项目/分享）+ 详情页模板？还是先不管分享详情（因为分享是空的）？
2. **样例数据**：2 篇真实论文 + 1 个真实项目。这 3 条由 owner 提供真实内容，还是先用占位假数据把结构跑通？（真实内容能验证字段够不够用，但需要 owner 花时间整理）
3. **跑通的判定**：`npm run dev` 能开、四个页面能访问、论文详情能打开、图片能显示、`npm run build` 无报错 —— 还需要什么？
4. **设计文档写到什么颗粒度**：只写结论，还是连每个字段的填写示例都要给？
5. **设计文档放哪**：`.scratch/phd-personal-site/` 下，还是 `docs/` 下（与已有两份调研文档并列）？
6. **样式要做到什么程度**：完全裸 HTML、还是一套最简 CSS（能读、移动端不溢出、不追求美观）？
